## Step 2 — Fix list (fix every item that failed the audit above)

### Critical security fixes (fix these first, no exceptions)

**1. gym_id scoping**
Every single database query in `NotificationService.java` must include `gym_id` as a filter. If any query fetches notifications without filtering by `gym_id`, fix it immediately. A member from Gym A must never see notifications from Gym B.

Check every method:
```java
// WRONG — missing gym scope
notificationRepository.findByUserId(userId);

// CORRECT
notificationRepository.findByUserIdAndGymId(userId, gymId);
```

**2. Role enforcement on admin endpoints**
Verify that `POST /api/v1/notifications/send` and all admin endpoints reject requests from `MEMBER` and `COACH` roles with `403 Forbidden`. This must be enforced in the backend via `@PreAuthorize` or equivalent — not just hidden in the frontend.

**3. Ownership check on mark-as-read and delete**
Before marking a notification as read or deleting it, verify the notification belongs to the requesting user AND their gym:
```java
Notification notification = notificationRepository.findByIdAndUserIdAndGymId(id, userId, gymId)
    .orElseThrow(() -> new ResourceNotFoundException("Notification not found"));
```

### Backend fixes

**4. Missing DB migration**
If the new columns or tables were not created via a proper migration file, create one now:
- File: `src/main/resources/db/migration/V2__extend_notifications.sql` (or next version number)
- Must include: `gym_id`, `sender_id`, `title`, `title_ar`, `is_read`, `read_at`, `priority`, `status`, `scheduled_at`, `sent_at`, `action_url`, `metadata`, `audience_type` on the `notifications` table
- Must include: `notification_settings` table
- Must include: `notification_preferences` table  
- Must include: `push_subscriptions` table
- Use `ADD COLUMN IF NOT EXISTS` to avoid breaking existing data

**5. Scheduler not triggering**
If `NotificationScheduler.java` was created but scheduling is not working, check:
- `@EnableScheduling` must be on the main application class or a `@Configuration` class
- `application.properties` must have `spring.task.scheduling.enabled=true`
- Cron expressions must be valid

Add to `application.properties` if missing:
```properties
spring.task.scheduling.enabled=true
notification.cron.expiry-check=0 0 9 * * ?
notification.cron.inactive-check=0 0 10 * * MON
notification.cron.scheduled-send=0 * * * * ?
```

**6. Duplicate prevention missing**
If automatic notifications do not check for duplicates before inserting, add this check to every automatic notification method in `NotificationService.java`:
```java
boolean alreadySent = notificationRepository.existsByUserIdAndTypeAndGymIdAndSentAtAfter(
    userId, type, gymId, LocalDateTime.now().minusDays(7)
);
if (alreadySent) return; // skip silently
```

**7. VAPID keys not configured**
If `PushNotificationService.java` was created but VAPID keys are not configured:
- Add to `application.properties`:
```properties
push.vapid.public-key=${VAPID_PUBLIC_KEY:}
push.vapid.private-key=${VAPID_PRIVATE_KEY:}
push.vapid.subject=mailto:admin@qawi.com
```
- The app must start without errors even if VAPID keys are empty (push is optional)
- If keys are empty, push sending should log a warning and skip, not throw an exception

**8. Missing web-push dependency**
If `pom.xml` does not include the web-push library, add:
```xml
<dependency>
    <groupId>nl.martijndwars</groupId>
    <artifactId>web-push</artifactId>
    <version>5.1.1</version>
</dependency>
```

**14. Service worker not registered**

```javascript
    body: data.body ?? '',
    icon: '/icon-192.png',
    dir: data.lang === 'ar' ? 'rtl' : 'ltr',
    lang: data.lang ?? 'ar',
    data: { actionUrl: data.actionUrl },
  });

  const url = event.notification.data?.actionUrl;
```

