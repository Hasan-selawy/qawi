# BACKEND ENDPOINTS

Add new gym admin staff endpoints.

Base path:

/api/v1/admin/employees

Only GYM_ADMIN can access these endpoints.

All results must be gym-scoped.

Never trust gymId from frontend.

Always use gymId from authenticated user.

---

## GET /api/v1/admin/employees

Returns all staff users in the gym.

Include users where role is:

* COACH
* SALES
* RECEPTIONIST

Do not include:

* MEMBER
* GYM_ADMIN
* SUPER_ADMIN

Response item:

id

name

email

phoneNumber

role

isActive

createdAt

lastLoginAt if available, otherwise null

memberCount if role = COACH and data is available, otherwise 0

---

## POST /api/v1/admin/employees

Create new staff user.

Request:

name

email

phoneNumber

role

password optional

autoGeneratePassword boolean optional

Allowed roles:

* COACH
* SALES
* RECEPTIONIST

Validation:

name required

email required

phoneNumber required

role required

email must be unique

role must be allowed

If password is missing and autoGeneratePassword = true:

generate a secure temporary password.

If password is provided:

hash with BCrypt like existing users.

Created user:

gymId = authenticated Gym Admin gymId

role = selected role

isActive = true

Return:

id

name

email

phoneNumber

role

temporaryPassword only if auto-generated

Important:

Only return temporaryPassword once in the response.

Do not store plain text password.

---

## PUT /api/v1/admin/employees/{id}

Update staff user.

Allowed fields:

name

phoneNumber

role

isActive

Do not allow changing email for now unless existing user edit pattern supports it.

Do not allow editing password here unless there is already password reset logic.

Security:

Employee must belong to same gym as authenticated Gym Admin.

Gym Admin cannot edit staff from another gym.

Gym Admin cannot edit SUPER_ADMIN.

Gym Admin cannot edit another GYM_ADMIN.

Allowed role changes:

COACH ↔ SALES ↔ RECEPTIONIST

But if changing away from COACH and the coach has assigned members:

block the change with a clear error:

"Cannot change this coach's role while members are assigned. Reassign members first."

If this check is difficult, then disable role changing for COACH users for now and show:

"Coach role cannot be changed yet."

---

## DELETE /api/v1/admin/employees/{id}

Do not hard delete by default.

Use soft deactivate.

Set:

isActive = false

Security:

Only same gym.

Cannot delete:

* SUPER_ADMIN
* GYM_ADMIN
* MEMBER

If role = COACH and coach has assigned members:

block deletion with:

"Cannot deactivate coach while members are assigned. Reassign members first."

If role = SALES or RECEPTIONIST:

allow deactivate.

Return success.

---

## PUT /api/v1/admin/employees/{id}/activate

Reactivate staff user.

Set:

isActive = true

Only same gym.

---
