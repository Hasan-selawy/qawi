═══════════════════════════════════════════
PART A — SYSTEM DESIGN RATIONALE
═══════════════════════════════════════════

For each major architectural decision below, explain:
1. WHAT was chosen
2. WHY it was chosen (the reasoning at the time)
3. WHAT ALTERNATIVES were considered or could have been used
4. WHAT TRADEOFFS this creates (what we gained, what we gave up)
5. WHAT PROBLEMS/STRUGGLES came up during development related to 
   this decision, and how they were resolved (if any occurred)

Cover at minimum these decisions — search the codebase to find 
the actual implementation details for each:

1. Multi-tenancy approach
   - No JPA @ManyToOne/@OneToMany relationships; gymId/memberId 
     as plain UUID columns instead
   - How isolation is enforced in the service layer
   - What this means for query performance, joins, and data integrity 
     at scale

2. Authentication & session strategy
   - JWT with 7-day expiry, no refresh token
   - JWT stored in localStorage (web) vs AsyncStorage (mobile)
   - BCrypt password hashing
   - Why no refresh token rotation was implemented
   - Security implications and what would change this for production

3. Database schema management
   - Hibernate ddl-auto=update with no migration tool (no Flyway/Liquibase)
   - Why this was acceptable during rapid development
   - What breaks or becomes risky in production with real customer data
   - Soft-delete pattern (isActive=false) instead of hard deletes — why

4. Feature flag implementation
   - Features stored as JSON strings in PlatformTier.features/featuresAr, 
     parsed via Jackson ObjectMapper in service layer
   - Why not a separate FeatureFlag entity/table with relations
   - How this scales as more features are added

5. Mobile networking architecture
   - Port-free API URLs (/api/v1 not :9000/api/v1) relying on 
     Replit's shared reverse proxy
   - EXPO_PUBLIC_DOMAIN environment variable approach
   - useProtectedRoute using firstSegment string instead of nested object
   - Why these choices were made in the Replit environment

6. Monorepo structure & workflow execution
   - pnpm workspaces with @workspace/ prefixes
   - Per-artifact Replit workflows instead of a single root dev command
   - No Vite proxy config — reliance on Replit's reverse proxy for 
     cross-service routing
   - Why this structure was chosen over alternatives 
     (e.g., separate repos, Nx, Turborepo)

7. Validation & error handling
   - Bean Validation (@Valid) + GlobalExceptionHandler with 9 
     exception types
   - Bilingual error messages (EN + AR) built into AppException
   - Why errors carry both languages instead of frontend-only translation

8. Rate limiting & request logging
   - Bucket4j for rate limiting, custom filters for request logging
   - Why these specific approaches vs. alternatives 
     (e.g., API gateway-level rate limiting)

9. Offline support (mobile)
   - Only check-in/check-out queued offline via AsyncStorage + NetInfo
   - Why other mutations require connectivity
   - What this means for gym environments with poor wifi

10. Auto-shift workout logic
    - MemberController.todaysWorkout() auto-slides uncompleted 
      workout days forward
    - Why this approach vs. strict calendar-based plans
    - Edge cases this does/doesn't handle

For each section, be honest — if something was a pragmatic shortcut 
under time pressure rather than a "best practice" choice, say so 
explicitly. The founder needs to know what is solid engineering 
vs. what is technical debt to revisit.
