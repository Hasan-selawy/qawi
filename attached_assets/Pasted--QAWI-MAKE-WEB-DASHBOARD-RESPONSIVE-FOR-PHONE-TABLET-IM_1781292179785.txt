# QAWI — MAKE WEB DASHBOARD RESPONSIVE FOR PHONE + TABLET

## IMPORTANT

Read CLAUDE.md and project documentation before making changes.

Do NOT rebuild the dashboard.

Do NOT redesign the entire UI.

Do NOT change backend logic.

Do NOT delete existing pages.

Do NOT create duplicate layouts.

Only patch the existing web dashboard layouts so they work properly on:

* mobile phones
* tablets
* small laptops
* desktop screens

The dashboard currently works best on desktop, but Qawi users will often use:

* phones
* iPads/tablets
* reception tablets
* sales phones
* gym owner phones

So the dashboard must be responsive.

---

# GOAL

Make the entire Qawi web dashboard responsive and usable on all screen sizes.

Target devices:

Mobile:

* 360px width
* 375px width
* 390px width
* 414px width

Tablet:

* 768px width
* 820px width
* 1024px width

Desktop:

* 1280px+
* 1440px+

---

# GLOBAL RESPONSIVE RULES

Use Tailwind responsive utilities.

Use breakpoints:

* mobile: default
* sm: 640px
* md: 768px
* lg: 1024px
* xl: 1280px

Do not allow the whole page to horizontally scroll.

Only specific components can scroll horizontally if needed:

* tables
* kanban boards
* calendar grids

Main app container should always fit screen width.

Cards should stack on mobile.

Large grids should become 1 column on mobile.

Tables should become scrollable or card-style on mobile.

Modals should fit mobile screens.

Buttons should be touch-friendly.

Minimum touch target:

44px height

---

# SIDEBAR RESPONSIVENESS

Current sidebar works on desktop.

Patch behavior:

## Desktop / large tablet

Sidebar stays visible on the left.

Width can remain current.

## Mobile / small tablet

Sidebar should collapse into a hamburger menu.

Top bar should show:

* hamburger icon
* page title or Qawi logo
* language toggle
* notifications
* user avatar

When hamburger is clicked:

* show sidebar as slide-over drawer
* dark overlay behind it
* clicking overlay closes sidebar
* clicking a nav item closes sidebar
* ESC key closes sidebar if implemented

Sidebar drawer width:

* 80% screen width on phone
* max 280px

Do not make dashboard content squeezed beside sidebar on mobile.

---

# TOP BAR RESPONSIVENESS

Top bar should never overflow.

On mobile:

* hide long role text if needed
* show avatar
* show initials
* keep AR/EN toggle
* keep notification icon
* page title can wrap or shrink

Use responsive text sizes.

---

# DASHBOARD CONTENT RESPONSIVENESS

All pages should use a responsive content wrapper:

Desktop:

* normal padding

Tablet:

* medium padding

Mobile:

* smaller padding

Example spacing idea:

* mobile: p-4
* tablet: p-5
* desktop: p-6 or p-8

Page titles:

* mobile: text-2xl
* desktop: text-3xl

Do not let page title overlap actions.

Top action buttons should wrap under the title on mobile.

# TABLES

Many pages use tables:

* Members
* Sales CRM
* Employees
* Subscriptions
* Revenue
* Reception alerts
* Nutrition staff members
* ZKTeco enrollments

Patch tables for mobile.

Use one of these patterns:

## Preferred for mobile

Convert rows into cards on mobile.

Each card shows labels:

Name: Sam
Phone: 079...
Status: Active
Actions: buttons

## Acceptable fallback

Wrap table in:

overflow-x-auto

and ensure table min-width is reasonable.

Important:

The whole page should not scroll sideways.

Only the table wrapper can scroll sideways.

# ACCESSIBILITY BASICS

---

# TECHNICAL RULES

Do not add a heavy UI framework.

Use existing Tailwind CSS.

Reuse existing components where possible.

If there is a Layout component, patch it globally.

If there are reusable Card/Table/Modal components, patch those first.

Avoid editing every page manually if shared components can solve it.

But inspect pages that have custom fixed widths.

Remove or replace problematic classes like:

* fixed desktop widths
* min-w too large on main containers
* overflow-hidden that cuts content
* absolute positioning that breaks mobile
* tables without overflow wrapper
* modals with fixed width only

---

# COMMON FIXES TO APPLY

Use:

w-full

max-w-full

min-w-0

flex-wrap

overflow-x-auto for table/kanban wrappers only

grid-cols-1 md:grid-cols-2 lg:grid-cols-3

text-sm md:text-base

p-4 md:p-6

gap-4 md:gap-6

hidden md:block where needed

block md:hidden where needed

Do not use:

w-screen inside nested layout if it causes overflow

fixed px widths without max-width

large negative margins
