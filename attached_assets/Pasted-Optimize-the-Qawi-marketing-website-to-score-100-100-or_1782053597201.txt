Optimize the Qawi marketing website to score 100/100

═══════════════════════════════
1. PERFORMANCE (56 → target 95+)
═══════════════════════════════

IMAGES:
- Convert all images to WebP format with fallback
- Add explicit width and height attributes to every 
  <img> tag to prevent layout shift (CLS)
- Lazy load all images below the fold: loading="lazy"
- Compress all images — no image should exceed 200KB
- If using a phone mockup illustration, convert it 
  from PNG to SVG if possible (much smaller file size)
- Add fetchpriority="high" to the hero section's 
  largest image if any

FONTS:
- Preload critical fonts in <head>:
  <link rel="preload" href="/fonts/inter-var.woff2" 
   as="font" type="font/woff2" crossorigin>
- Use font-display: swap on all @font-face rules
- Subset fonts to only the characters needed 
  (Latin + Arabic) instead of loading full font files
- Self-host fonts instead of loading from Google Fonts 
  CDN to eliminate the extra DNS lookup and request

JAVASCRIPT:
- Audit bundle size with build tool analyzer
- Code-split any route that isn't the landing page itself
- Remove unused JavaScript and CSS (check for unused 
  Tailwind classes via PurgeCSS/content config)
- Defer non-critical JavaScript:
  <script defer src="...">
- If using animation libraries (Framer Motion, etc.), 
  verify they're tree-shaken and only animated 
  components are imported

CSS:
- Inline critical above-the-fold CSS in <head>
- Defer non-critical CSS loading
- Minify all CSS and JS for production build
- Remove any unused CSS from the bundle

RENDERING:
- Eliminate render-blocking resources
- Use CSS containment (contain: layout) on 
  independent sections like the feature cards grid
- Avoid layout shift from the floating phone 
  mockup animation — reserve space with explicit 
  dimensions before animation starts

CACHING:
- Set long cache headers for static assets:
  Cache-Control: public, max-age=31536000, immutable
- Use a CDN (Cloudflare, Vercel Edge) for static assets
- Enable Brotli or gzip compression on the server

═══════════════════════════════
2. ACCESSIBILITY (96 → target 100)
═══════════════════════════════

- Run axe DevTools or Lighthouse accessibility 
  audit and fix every flagged issue specifically
- Ensure every interactive element (buttons, links) 
  has a minimum touch target of 44x44px
- Add aria-label to icon-only buttons (e.g., 
  language toggle, App Store/Google Play badges)
- Verify color contrast ratio is at least 4.5:1 
  for all text — check the muted gray text 
  (#94A3B8 or similar) against the dark navy 
  background especially in feature card descriptions
- Add alt text to every image, including decorative 
  ones (use alt="" for purely decorative images, 
  not missing alt entirely)
- Ensure all form inputs (if any signup form exists) 
  have associated <label> elements
- Verify focus states are visible on all interactive 
  elements (buttons, links) — add a visible 
  focus ring: focus-visible:ring-2 focus-visible:ring-green-500
- Test full keyboard navigation — Tab through the 
  entire page and verify logical order, no traps
- Add skip-to-content link for screen reader users
- Verify heading hierarchy is correct: one <h1>, 
  then <h2> for major sections (Features, Pricing, 
  Roles), <h3> for sub-items — do not skip levels
- For the language toggle (عربي), ensure the 
  lang attribute on <html> changes when language 
  switches, and dir="rtl" is set correctly

5. RENDERING STRATEGY (IMPORTANT)
═══════════════════════════════

If this landing page is currently a client-side 
rendered React SPA, this is likely the #1 cause 
of low Performance and SEO scores combined.

STRONGLY RECOMMEND:
Rebuild the marketing site specifically (not the 
app dashboard) using Next.js with Static Site 
Generation (SSG) or migrate to a static site 
generator. This is separate from the main Qawi 
web dashboard (which can stay as a React SPA 
since it's behind login and SEO doesn't matter there).

A static-generated marketing page will:
- Load near-instantly (Performance 90+)
- Be fully crawlable by Google (SEO 100)
- Reduce JavaScript bundle size significantly
- Eliminate most layout shift issues

If a full Next.js migration isn't feasible right 
now, at minimum ensure the current React build 
pre-renders the initial HTML (via Vite SSR plugin 
or prerendering the static marketing page at build time).
